# 設計文件：口播＋動態 PPT 文案背景 視頻自動包裝管線

日期：2026-11-26
狀態：待審核

## 1. 意圖（Intent & Why）

使用者提供一支口播影片 MOV（畫面是主體人物講話，字幕已燒進畫面、無獨立文字稿）。目標是把這支素材自動包裝成一支 1080×1920 豎版短視頻：背景是「動態 PPT 知識卡片」風格的提煉文案，人物以畫中畫（PiP）呈現在角落，全片文字動畫嚴格對齊人聲時間軸。省去人工逐句對時間、手動排版、手動合成的重複勞動。

## 2. 目標 / 非目標 / 反目標

### 目標
- 從 MOV 自動抽音頻，用 faster-whisper（`large-v3`）轉錄，輸出含**句子級＋詞級時間戳**的 `transcript.json`。
- 由 Claude（充當文案策劃師）把逐字稿提煉成 3~6 頁 PPT 結構（金句＋高亮詞），輸出 `slides.json`（方案 A，離線完成）。
- Remotion 依 `slides.json` 與時間戳，渲染「動態排版背景＋畫中畫」，輸出 1080×1920 / 30fps / ≤2:59 的 mp4。
- 渲染前先出 2~3 張關鍵幀截圖自檢，避免文字溢出與畫中畫遮擋。

### 非目標（本次不做）
- 不做「照抄口語」式字幕（原 MOV 已燒入字幕，PiP 保留原樣即可）。
- 不做語音克隆／數字人驅動；人物就是原始 MOV 畫面。
- 不做多素材批次併行（先支援單支 MOV 一條龍）。

### 反目標（技術上能跑但算失敗）
- 文字動畫與人聲明顯不同步（時間戳對不準）。
- 畫中畫遮擋 PPT 文字，或文字溢出畫面。
- 中文錯別字／斷句錯誤多到影響閱讀。
- 輸出不是 1080×1920、或時長超過 2:59。

## 3. 約束（Constraints）
- 運行環境：macOS（Darwin 23.6.0）。已裝 Node v22.22.3、npm 10.9.8、FFmpeg 8.1.1（含 ffprobe）。
- **faster-whisper 尚未安裝**（需 Python venv + `pip install faster-whisper`）。
- **Remotion 尚未安裝**（需 `npm` 初始化 React 版專案）。
- Whisper 模型固定 `large-v3`、語言 `zh`、CPU 推論（CTranslate2 `int8`）。
- 第二步（文案策劃）由 Claude 離線完成，**不接 Claude API**、不引入額外成本。
- 輸入 MOV 的解析度／長寬比未知，畫中畫的裁剪策略需在拿到實檔後依其屬性決定。
- 字體：**繁體中文（台灣）**，默認 PingFang TC（macOS 系統字體），備選 Noto Sans TC；全文以繁體中文呈現。

## 4. 管線總覽（前置裁剪＋四步）

### 第零步：素材裁剪（如素材可能超長）
1. `ffmpeg` 抽音頻並以 `silencedetect` 偵測靜音區段（開頭、結尾、中間）。
2. 裁剪規則（依使用者指示）：
   - 開頭：剪去開頭小段「暫停／無聲」畫面。
   - 結尾：剪去結尾無聲的說話間隔。
   - 中間：剪去中間「無聲的說話間隔」畫面（僅在總時長仍 >2:59 時，由最長間隔依序剪）。
3. 輸出 `input.trimmed.mov`（≤2:59）；**後續所有步驟以裁剪後素材為準**，確保時間戳與最終成片一致。

### 第一步：音頻提取與精準時間軸轉錄
1. `ffmpeg` 從 `input.mov` 抽音頻 → `audio/input.wav`（16kHz、單聲道、PCM）。
2. `faster-whisper`（`large-v3`、`language="zh"`、`word_timestamps=True`）轉錄。
3. 產出 `transcript.json`（句子級＋詞級 start/end）。
4. 錯別字與標點修正（對使用者而言全自動、無需手動介入）：標點由腳本做輕量規則補正；**明顯錯別字（同音字）由 Claude 在第二步閱讀時一併校正**，並回寫校正後版本到 `transcript.json`。修正採**原地替換**（改字／補標點，不改動詞數與句界），確保校正後文字仍對齊原始 `words[]`／`segments[]` 時間戳；**不做句子重切分**。

### 第二步：PPT 結構化文案提煉（核心大腦，方案 A）
由 Claude 讀 `transcript.json`，完成：
1. 理解口播核心邏輯。
2. 劃分 **3~6 個邏輯段落**（對應 PPT 頁），每段起止時間戳**嚴格對齊語音**。
3. 每頁產出：
   - **主標題**：≤10 字，概括該段核心觀點。
   - **重點列表 2~4 條**：每條 ≤15 字，提取數據／金句／步驟。
   - **高亮詞**：在每條內標註需「動態高亮」的核心詞彙。
4. 輸出 `slides.json`（結構見 §5）。

### 第三步：Remotion 動態排版與畫中畫合成
1. Remotion React 專案，`1920×1080` 旋轉為 `1080×1920`（豎版）、30fps。
2. 視覺佈局（見 §6）＋文字動畫＋畫中畫＋音頻（保留原聲，可選極低音量墊樂）。

### 第四步：視覺自檢與渲染輸出
1. `renderStill()` 渲 2~3 個關鍵時間點（如第 3 秒、第 15 秒）截圖。
2. 人工／腳本檢查：文字溢出？PiP 遮擋？若有，調整 CSS 後重渲。
3. 確認後 `npx remotion render` 輸出 `output/日期-主題.mp4`。

## 5. 資料契約（步驟間的關鍵介面）

### `transcript.json`
```json
{
  "audio_file": "audio/input.wav",
  "language": "zh",
  "model": "large-v3",
  "segments": [
    {
      "id": 0,
      "start": 0.0,
      "end": 3.2,
      "text": "今天跟大家聊一個話題。",
      "words": [
        { "word": "今天", "start": 0.0, "end": 0.5 },
        { "word": "跟", "start": 0.5, "end": 0.7 }
      ]
    }
  ]
}
```

### `slides.json`
```json
{
  "title": "影片主題",
  "duration": 179.0,
  "slides": [
    {
      "index": 0,
      "start": 0.0,
      "end": 28.0,
      "chapterLabel": "開場",
      "title": "主標題（≤10 字）",
      "bullets": [
        {
          "text": "重點列表條目（≤15 字）",
          "start": 0.0,
          "end": 12.0,
          "highlight": [
            { "word": "高亮詞", "start": 5.0, "end": 5.6 }
          ]
        }
      ]
    }
  ]
}
```

**時間軸所有權（關鍵決策）**：Claude（第二步）是所有動畫時間的唯一來源。每頁 `start`/`end` 對齊來源 `segments[]` 時間戳；每條 bullet 與每個 highlight 都帶顯式 `start`/`end`，對齊來源的 `words[]`／`segments[]` 時間戳。渲染端**不做字串模糊匹配**，直接讀取這些時間戳驅動動畫。

## 6. Remotion 視覺設計（使用者已定）

- **背景層（PPT 知識卡片風）**：乾淨高級的淺色商務漸變背景，帶微弱網格或質感紋理；頂部顯示進度條或章節標籤。
- **文字動畫**：依 `transcript.json` 精準時間戳，當講者講到對應內容時，標題與列表項依次平滑淡入／上滑出現；核心詞彙觸發**動態高亮**（黃色底色標記，或字體放大＋變色）。
- **畫中畫（PiP）**：`input.mov` 裁剪後置於**右上角**，圓角矩形邊框、微陰影、細微「呼吸感」邊框線；確保不遮擋左側／上方的 PPT 文字。
- **音頻**：保留 `input.mov` 原始人聲；若目錄下有 BGM 檔則加極低音量墊樂，否則僅原聲。
